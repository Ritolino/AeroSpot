## [1.6.1] — 2026-11-20 (1-Click Auto-Update, Native RTF/ODT & Search/Drag-Drop Fixes)

### Added
- **1-Click Automatic Update System (Portable `.zip` & Setup `.exe`) + Startup Floating Pill (`UpdateService.cs`, `IpcMessage.cs`, `WorkerManager.cs`, `HostWindow.cs`, `FloatingNotificationWindow.xaml.cs`, `App.xaml.cs`, `SettingsWindow.xaml.cs`):**
  - Added smart asset selection in `UpdateService.CheckForUpdatesAsync` (`isPortable` prioritizes `.zip`, non-portable prioritizes `.exe` with `.zip` fallback) and automatic `SHA256SUMS.txt` download and SHA-256 integrity verification (`VerifyIntegrityAsync`).
  - Implemented `PrepareAndApplyUpdateAsync` & `StageZipUpdate` for 1-click self-updating of portable `.zip` packages: validates archive contents (`AeroSpot.exe`, `app\AeroSpot.Host.exe`), enforces a dev-directory safety guard (`AeroSpot.sln`), runs an isolated hidden `apply_update.ps1` script that cleanly waits for all processes to exit via new IPC `IpcMessageType.ShutdownHost` (21), replaces binaries while strictly excluding `Data\` and preserving `portable.txt`, relaunches AeroSpot, and cleans up staging files.
  - Enhanced `HostWindow.ScheduleAutomaticUpdateCheck` with resilient startup retries (`10s` → `45s` → `120s`), post-update detection via `LastKnownVersion` showing a 5-second green confirmation pill (`"✓ AeroSpot aggiornato alla vX.Y.Z!"`), and new IPC `IpcMessageType.ShowUpdateNotification` (22) displaying an interactive dark `FloatingNotificationWindow` pill with a direct `"🚀 Aggiorna ora"` action button and live 0%→100% download progress.
- **Spotlight Drag & Drop Behavior Selector (`AppConfig.cs`, `SettingsWindow.xaml`, `SettingsWindow.xaml.cs`, `MainWindow.xaml.cs`):**
  - Added `SpotlightDragDropMode` (`WindowsDefault`, `AlwaysCopy`, `AlwaysMove`) configurable in **Settings → Spot**. `AlwaysMove` sets `Preferred DropEffect = DROPEFFECT_MOVE (2)` on `DataObject` for cross-volume Explorer moves while retaining `Copy` fallback for external apps (WhatsApp, browsers). Applications and system directories remain strictly protected in `Copy | Link` across all modes.
- **3D Viewer "↺ Reset vista" Button & Universal `R` Shortcut (`PreviewWindow.xaml`, `PreviewWindow.xaml.cs`, `LocalizationService.cs`):**
  - Added clickable **"↺ Reset vista"** button in the `PreviewWindow` header bar (`BtnReset3DView`) and localized the bottom-right `StlView` hint text (`Preview_Stl_Hint`).
  - Added `ResetStlCameraView()` integrated into `ResetZoom()` and bound the universal **`R`** keyboard shortcut (when no modifiers are pressed and focus is not in a text box) to reset view/zoom across 3D models (`.stl`/`.3mf`), images, PDFs, and PreviewHandlers.
- **Native In-Process `.rtf` & `.odt` Readers + 1-Click PDF Export (`RtfReader.cs`, `DocxReader.cs`, `PreviewLoader.cs`, `MediaConversionService.cs`):**
  - Implemented `RtfReader` (100% managed C# in-process RTF parser with ANSI codepage `1252`, Unicode `\uN` escapes, bold/italic/strike Markdown formatting, and ignored metadata destinations) and `DocxReader.ReadOdt` (native OpenDocument ZIP/XML reader for `.odt` headings, paragraphs, lists, and tables).
  - Integrated `.rtf` and `.odt` into `PreviewLoader` (native Dark Fluent `MarkdownView`, zero disk locks) and `MediaConversionService.ConvertDocumentToPdfAsync` (1-click PDF export).

### Fixed
- **Total Block of `WINWORD.EXE -Embedding` & Office COM Zombie Processes (`PreviewHandlerResolver.cs`, `PreviewLoader.cs`):**
  - Added `BlockedHandlerClsids` in `PreviewHandlerResolver` to permanently block Microsoft Word (`{84F66100-FF7C-4fb4-B0C0-02CD7FB668FE}`), Excel (`{00020827-0000-0000-C000-000000000046}`), and PowerPoint (`{65235197-874B-4A07-BDC5-E65EA825B718}`) COM Preview Handlers across all extensions.
  - Closed fallback leaks in `PreviewLoader` for corrupted/password-protected `.docx`/`.docm`/`.dotx`/`.xlsx`/`.xlsm`/`.xltx`/`.rtf`/`.odt` files and explicitly intercepted `.doc`/`.dot`/`.xls`/`.ppt`/`.pptx` with safe `PreviewType.Generic` metadata cards so `WINWORD.EXE -Embedding` can never be spawned.

- **Shortcut Files (`.lnk` / `.url`) Excluded from Spotlight Search (`PathFilter.cs`, `SqliteIndexDatabase.cs`):** Excluded `.lnk` and `.url` shortcut files from indexing in `PathFilter.IsPathAllowed` and purged existing `.lnk`/`.url` records on database initialization (`Initialize()` and `PurgeSystemJunkFiles()`), while preserving installed apps via `shell:AppsFolder` and `Program Files` executables.

Added `NotifyItemMovedOrDeleted` to immediately purge moved items from `index.db` and `FilteredResults`.
- **3D Viewer (`.stl` / `.3mf`) Full-Background Mouse Hit-Testing & Anti-Disappear Zoom Clamp (`PreviewWindow.xaml`, `PreviewWindow.xaml.cs`):** Moved mouse rotation and wheel handlers from `StlViewport` (which only hit-tests rendered mesh triangles) to the parent `StlView` container (`Background="#0A0F1D"`), and clamped camera zoom distance proportionally to `_stlDefaultDistance` (`[0.18x, 4.5x]`) with scaled near/far clipping planes so 3D parts never vanish.
- **Spotlight Two-Phase SQLite Search (`Title > FullPath`), Dominant Category Hierarchy & Program Files `\bin\` Exemption (`SqliteIndexDatabase.cs`, `SearchRanker.cs`, `PathFilter.cs`, `AppsFolderScanner.cs`, `AppConfig.cs`):**
  - Replaced the single un-ordered `LIMIT 150` SQL query with a two-phase search (Phase 1: ordered `Title` matches `LIMIT 250`; Phase 2: fallback `FullPath` matches `LIMIT 100`), preventing hundreds of internal folder files from truncating apps like `OBS Studio.lnk` or `esempio.exe`.
  - Separated `SearchRanker` into a strict Title tier (`>= 100,000` pts) above Path-only matches (`< 10,000` pts), with user Category Hierarchy always commanding order among Title matches (`5,000` pts/step) and `PrioritizeExactNameMatches` (default `false` in `SchemaVersion = 5`) boosting exclusively 100% exact title matches (`+500,000` pts).
  - Exempted `Program Files` and `Program Files (x86)` from `\bin\` and `\obj\` developer directory exclusions so installed executables like `C:\Program Files\obs-studio\bin\64bit\obs64.exe` are indexed, and replaced hardcoded drive checks in `AppsFolderScanner` with `PathFilter.GetAllowedDriveLetters()`.

### Changed

## [1.6.0] — 2026-11-17 (Native PDFium, Explorer Batch Tools & Foreground Fix)

### Fixed
- **QuickLook Foreground Activation Block on Cold Startup (`AllowSetForegroundWindow` + `ForceForegroundWindow`):** Fixed an issue where pressing Spacebar in File Explorer before opening Spotlight at least once (`Alt + Space`) caused QuickLook to open behind Explorer or fail to steal focus due to Windows foreground lock restrictions on pre-warmed background `AeroSpot.Worker` processes and WPF's cached `Topmost` state. Added `Win32.AllowSetForegroundWindow(ASFW_ANY)` across low-level keyboard hook (`KeyboardHookManager`), `HostWindow`, and PID-targeted calls in `WorkerManager`, paired with `Win32.ForceForegroundWindow` (`AttachThreadInput` + `SetWindowPos(HWND_TOPMOST)` + `BringWindowToTop`) and explicit `Topmost` resets in `PreviewWindow.HidePreview()` / `ShowPreviewForFileAsync()` and `MainWindow.ShowOnActiveMonitor()`.
- **QuickLook Hidden Behind Explorer Toggle Loop & `StopDynamicTracking` Race Condition:** When QuickLook loses focus (`QuickLookAlwaysOnTop = false`) and slips behind File Explorer, pressing Spacebar on the same item now brings QuickLook back to the foreground instead of silently toggling it off. Fixed a race condition in `HostWindow.OnQuickLookCloseRequested` / `StartDynamicTracking` where resetting `_lastActivePreviewPath = null` while the polling thread was resolving a path caused QuickLook to silently reopen 2 ms after closing.
- **First-Open Positioning in `PositionWindowRelative` (`PreviewWindow`):** Removed redundant startup `Show()`/`Hide()` from `App.OnStartup` and ensured `ApplyModelToUI`/`PositionAndSizeWindow` run before `Show()`, preventing `PositionWindowRelative` from misclassifying first-time previews as already-visible and preserving accurate active-monitor centering and Spotlight side-by-side placement.
- **Deploy Script Recovery (`scripts\deploy-local.ps1`):** Restored `deploy-local.ps1` using direct launcher execution (`Start-Process -FilePath $launcher -WorkingDirectory $TargetDir`) to prevent third-party antivirus heuristic false positives and reboots.
